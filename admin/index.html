Get Started

If you want to edit the main website, you need GitHub, and be part of the organisation, and change the HTML of the pages in the public website repository. The files for these are in the `assets` folder. If you need to add pages on, and you don't know how to code beyond write HTML / edit it, please feel free to contact the webmaster (or previous webmasters, for new webmasters).
The only thing that can be editted via the intranet is the president / FACSO bios, as displayed on the front website, and the societies / sports / committees, which also can be editted via the intranet.
The intranet is pretty much dynamic. If you have skills in NodeJS, feel free to edit in the intranet repository, noting that `pageCommands` is the directory for the code that does anything for each page (POST, GET) - use examples from other pages if you want to add anything on. You can test locally by `npm install` and `node local.js`. It is set up to auto-deploy if you commit, and merge to the `main` branch.
Information on how to test the system locally, and implement anything, is on the GitHub. Please also note that deployments are made on the `main` branch, but you can not commit directly to it - please use a branch, and pull.

Encryption

We require some data to be encrypted. This includes:

  • CIS codes of all students at the college - however, once they log in, they will be saved in the database as plain text. This is because the encrypted version tells us if they are authorised to use the system - but everyone has not consented to us using their data. If they have signed in, they have consented.
  • College families; encrypting the children's CIS codes, but keeping parents as plain text - so we can put them in family trees automatically, and link them in the future. The parents have consented to be there, hence they are in plain text.
We are using the idea of encryption Adam Johnstone (FACSO, 2025-26) used. This includes:
  • Each line containing the hash (encrypted data), and a salt (32 hexadecimal characters - random)
  • The encrypted data is what is formed when we encrypt the salt + CIS + pepper. The CIS is all lowercase, the salt is unique to the line, and the pepper is pre-set. Please ask previous webmasters on how to derive this pepper.
  • Encryption is done in SHA-256
  • For example, let us say our salt for the line is `ca9e6064a3ff4d4d74e6d2434be75426`, our CIS code is `abcd12`, and our pepper is `JoBo`. Then we encrypt the string `ca9e6064a3ff4d4d74e6d2434be75426abcd12JoBo`, to get `77b19f4fb0af2c5f3e845b513c009c1935c6f47d2bb1d8eb93f8e65e0ff596c9` for this line
This must be done by the FACSO or President, before passing it off to the Webmaster to put onto the system - this is because only they are allowed to see a list of CIS codes.
